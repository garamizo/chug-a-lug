# Photo Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tab tap opens the camera; the drink exists and counts only when its photo reaches the server, written
with it in one transaction; the photo is Freight captioned with the drink; Undo removes both.

**Architecture:** `media` gains `drink_kind`; the media create hook, inside one transaction, saves the media and a
`drink_entries` row with the same id. `drink_entries.createRule` closes. A model delete hook on drinks removes the
paired media; proof media is immutable. The client sends one multipart create per tap, then reads the drink back.

**Tech Stack:** PocketBase 0.40.4 JS hooks + migrations, SvelteKit 5, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-16-photo-tab-design.md`

## Global Constraints

- User-visible strings only in `web/src/lib/labels.ts`; README glossary is the source of truth for names.
- Labels, verbatim: `tabProofHint: 'Snap it to count it.'`, `tabSending: 'Sending…'`, `tabRetry: 'Retry'`,
  `proofNeedsImage: 'Take a photo — a video does not count.'`, `proofNeedsStop: 'Drinks count at a stop on today’s route.'`
- Server error codes, verbatim: `proof_needs_image`, `proof_needs_stop`, `proof_locked` (400).
- Proof kinds: `beer, cocktail, shot, water, food`. Proof drink id === its media id.
- Migration file `pocketbase/pb_migrations/1759300000_photo_tab.js` (newest is `1759200000_run_home.js`).
- Offline writes are still not queued. Retry lives only in memory while the send's scope is current.
- Hooks: top-level consts are invisible inside callbacks (`live.pb.js:1-2`); inside `runInTransaction` use the tx app,
  never `$app` (`action_order.pb.js:1-2`).
- One test harness at a time: check `ss -ltn | grep -E ':(15173|1809[0-5]|1252[56])\b'` is empty first. Never ports
  8090/3000. Stage explicit paths; never `--no-verify`.

## Review Focus

1. A failed second save inside the proof transaction must leave no media, no drink, and no consumed `action_order`
   value — tested by injection in Task 1.
2. A send that completes after logout, route switch, Chicago midnight or a sim-run change must not appear in the newly
   displayed feed and must not offer Retry — Task 2 unit test.
3. Lost response: the create landed but the client saw an error; Retry gets 400 duplicate id and must count it as
   done, never create a second drink — Tasks 1 (server) and 2 (client).
4. A proof shows once in Crew Chat (photo entry, Cheers on `media`), while legacy drinks without photos keep their
   announcement — Task 2.
5. Cancelling the camera picker changes nothing (no pending state left behind) — Task 3 e2e.

### Task 2: Client logic — sending a proof, counting, chat

**Files:**
- Create: `web/src/lib/live/proof.ts`
- Modify: `web/src/lib/types.ts` (`Media.drink_kind?: DrinkKind | ''`, `DrinkEntry.media?: string`),
  `web/src/lib/live/tab.ts` (drop `withPending` from counting paths), `web/src/lib/live/chat.ts`
  (`chatEntries` skips `drink:` entries whose drink has `media`), `web/src/lib/labels.ts` (the five labels;
  `proofCaption`)
- Test: `web/tests/unit/proof.test.ts`, `web/tests/unit/chat.test.ts`, `web/tests/unit/tab.test.ts`,
  `web/tests/unit/labels.test.ts`

**Interfaces:**
- Consumes: Task 1's server contract.
- Produces:
  ```ts
  export type ProofScope = { user: string; itinerary: string; stop: string; day: string; runId: string | null };
  export type ProofSend = { id: string; kind: DrinkKind; scope: ProofScope; file: File; takenAt: string };
  export type ProofResult =
    | { status: 'saved'; drink: DrinkEntry | null; media: Media }   // drink null when the read-back failed
    | { status: 'stale' }                                           // scope no longer current; nothing to upsert
    | { status: 'failed'; message: string };                        // keep for Retry
  export function proofForm(send: ProofSend): FormData;             // id, user, stop, kind=image, taken_at, drink_kind, file
  export async function sendProof(send: ProofSend, deps: {
    createMedia: (form: FormData) => Promise<Media>;
    getDrink: (id: string) => Promise<DrinkEntry>;                   // expand user,stop
    currentScope: () => ProofScope | null;
  }): Promise<ProofResult>;
  export function proofCaption(kind: DrinkKind | '' | undefined, author: string): string; // "🍺 Beer · Ana"; author only when no kind
  ```
  `sendProof`: create → on 400 whose data shows a duplicate `id`, try `getDrink(id)`; found → `saved`. Network/other
  error → `failed` (message `copy.noSignal` for status 0, server message mapped for `proof_needs_image` /
  `proof_needs_stop`, else `copy.uploadFailed`). After success, `getDrink`; failure → `saved` with `drink: null`.
  Before returning `saved`, compare `currentScope()` to `send.scope` (all fields) → `stale` if different.

  case). `labels.test.ts` — the five labels verbatim; `proofCaption('beer','Ana')`.
