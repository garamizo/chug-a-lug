# Join Link Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace peer-approved boarding, Google sign-in, emailed sign-in codes and Turnstile with one Conductor-made join link (seats + expiry) and email + password sign-in.

**Architecture:** A `join_links` collection made through a host-only, secret-guarded PocketBase route that `just invite` calls with `curl`-style `fetch`. A `signups` collection holds pending email verifications; verifying a code creates the user, takes a seat in the same transaction and answers a session. The old boarding server, its UI and its env keys are removed; the Manifest keeps people, Put off / Let back on and the access log.

**Tech Stack:** PocketBase 0.40.4 JSVM hooks + JS migrations, SvelteKit 2 / Svelte 5, Vitest (unit + hooks), Playwright (e2e).

**Spec:** `docs/superpowers/specs/2026-11-15-join-link-design.md` — read it first; this plan cites its sections (§).

## Global Constraints

- PocketBase 0.40.4 JSVM; migrations are self-contained (their tests run with an empty hooks dir).
- User-visible strings only in `web/src/lib/labels.ts`; the README UI glossary is the source of truth for names.
- Times are UTC in the DB and API; America/Chicago only for display.
- Stage explicit paths, never `git add -A`; read `git status --short` before each commit.
- Tests first. Each task ends green: `cd web && npm test && npm run check && npm run test:e2e`, plus `bash scripts/test-hooks.sh` (one test run at a time across worktrees: ports 15173/18093, 18090/18091/18095, 12525–12528).
- Never touch ports 8090/3000 (live stack) from tests.
- Limits (§4.2): `join:<ip>` 20/h spent only for a valid form; `join-mail:<sha256(email)>` 3/h and `join-mail-link:<link id>` 40/h spent by every code mail; ≤ 10 open sign-ups; `/join/link` 30/h per IP; sign-up life 60 min, code 15 min, 5 wrong codes, resend once a minute and 3 per sign-up, refused with < 15 min of life left.
- Link: seats 1–50, days 1–60 (default 14), token `$security.randomString(32)`, only `crew.hash(token)` stored, a new link revokes every other.
- Link message (every dead-link answer): 410 `This link is used up or expired. Ask the Conductor for a new one.`

## Plan decision

The spec's single migration is split in two so every task stays green: `1759100000_join_link.js`
(additive, Task 1) and `1759100001_retire_boarding.js` (destructive, Task 2). Together they do exactly §4.6.

## Review Focus

1. **Ten relatives on one Wi-Fi** sign up within the hour: all ten get codes; typo retries cost nothing. → Task 2 test `ten emails from one IP`.
2. **The verify answer is lost** (signal drop): retrying the same verify signs in without a second seat; a put-off user's retry is refused. → Task 2 tests; Task 3 client retry + 404 fallback.
3. **Reload during the code step** keeps the sign-up and does not ask for the link again. → Task 3 e2e.
4. **Email typed with capitals or spaces** at sign-up, then signing in with the lowercase form, works. → Task 2 test `normalised email signs in`.
5. **A link pasted with trailing punctuation** (`…#k3J9abc).` from a chat app) still works. → Task 3 unit test of `tokenFromHash`.
