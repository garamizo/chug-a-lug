# M3 review fixes

The live editor must reuse a submitted Bulletin's ID and edited text after a failed save. Restore its compose sheet on failure so a retry converges even when the first response was lost. A confirmed successful save ends that retry.

Bulletins need a periodic refresh after missed realtime events, sequenced after loading the route. The Crew Board needs subscriptions for roster, Tab and acknowledgements plus polling for reconnect recovery; dispose them on navigation and ignore obsolete responses.

Off the event's Chicago calendar day, every impossible leg must block Save. Keep the position selection requirement separate from whether earlier legs qualify as history, and share the rule between the editor and commit endpoint.

## Implementation and verification

1. Add failing regression tests for lost save responses, missed Bulletin events, live Crew Board changes, and off-day validation before writes.
2. Preserve failed Bulletin state; refresh Bulletins on the route poll; refresh and clean up Crew Board data; make the cohesion rule date-aware.
3. Run unit tests, Svelte checks, end-to-end tests and PocketBase hook tests sequentially. Use only the isolated test ports.

## Results

The new regressions failed on the original implementation: the lost-response test could not find the edited Bulletin, the Crew Board missed the new user, the poll never refreshed Bulletins, and an impossible off-day route returned 200 instead of 409.

After the fixes: 312 unit tests, 42 end-to-end tests, and 37 hook tests pass. Svelte/type checking reports zero errors and warnings. The date-boundary regression checks Chicago midnight; the commit regression verifies that an off-day rejection writes nothing while event-day history remains allowed.
